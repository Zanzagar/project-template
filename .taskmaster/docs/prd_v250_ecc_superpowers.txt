# Template v2.5.0 — ECC v1.8.0 + Superpowers v5 Integration

## Overview

Integrate the highest-value patterns from Everything Claude Code v1.8.0 and Superpowers v5.0 into our project template. This release focuses on four pillars: hook infrastructure (profile system, quality gate consolidation), developer experience commands (harness audit, model routing, session management), agentic engineering skills (eval-first loops, autonomous patterns), and security hardening (deny lists, AgentShield CI, reverse injection guardrails).

## Context

Research conducted 2026-03-18 across three sources:
- **Superpowers v5.0.0-v5.0.5**: Visual brainstorming, spec/plan review loops, architecture guidance, SDD model selection, instruction priority hierarchy. Template alignment committed in `cd43e05`.
- **ECC v1.8.0**: Hook profile system (`run-with-flags`), quality gate hook, cost tracker, harness audit, autonomous loops, agentic engineering, project auto-detection, security guide (212 actionable recommendations).
- **Claude Code official docs**: 22 hook events (up from 5 we use), prompt-based hooks, agent-based hooks, HTTP hooks, `TaskCompleted` event, `SessionEnd` event.

Current template state: v2.4.0 on main + Superpowers v5 alignment on `feature/superpowers-v5-alignment`. Template has 14 agents, 39 skills, 50 commands, 16 rules (9 core + 7 language), 18 hooks.

Key prior decisions that constrain this PRD:
- Hook-based enforcement stays (deterministic > probabilistic)
- Superpowers handles workflow orchestration (brainstorming, TDD, SDD)
- Task Master handles task decomposition (PRD → parse → expand)
- Our template adds the enforcement + observability layer around both

### Key Architecture Decisions

**Decision 1: Hook profile system uses environment variables, not config files**
- Alternatives: JSON config file, settings.json overlay, per-project profiles
- Rationale: Environment variables are runtime-toggleable without restarting sessions. ECC validated this approach across 4 platforms. `ECC_HOOK_PROFILE=minimal|standard|strict` + `TEMPLATE_DISABLED_HOOKS=id1,id2` gives maximum flexibility with zero config file changes.

**Decision 2: Quality gate consolidation merges 3 hooks into 1 smart hook**
- Alternatives: Keep separate hooks, add more granular hooks
- Rationale: ECC's quality-gate.js handles Biome/Prettier/gofmt/ruff with auto-detection and smart deduplication. One hook that detects the right tool is better than three hooks that each run regardless. Reduces PostToolUse overhead by ~60%.

**Decision 3: New hooks written in Node.js, existing hooks stay bash**
- Alternatives: Rewrite all hooks in Node.js, keep everything bash
- Rationale: Node.js hooks are cross-platform and ~50-100ms faster via require() optimization. But rewriting 18 working bash hooks is high-effort, low-value. New hooks (quality gate, cost tracker, file size guard, profile system) use Node.js. Existing hooks stay bash until natural rewrite opportunities arise.

**Decision 4: Harness audit uses deterministic scripted scoring, not LLM evaluation**
- Alternatives: LLM-based scoring, manual checklist
- Rationale: ECC's harness-audit.js computes scores from explicit file/rule checks — reproducible for the same commit. LLM scoring varies between runs. Deterministic scoring enables trend tracking across versions.

### Technical Constraints
| Constraint | Source | Impact |
|------------|--------|--------|
| Hook timeout default 10 min, configurable per hook | Claude Code docs | Cost tracker and quality gate must complete within timeout |
| PreToolUse is the only hook that can block actions | Claude Code docs | File size guard and profile system enforcement must use PreToolUse |
| Hooks communicate via stdin/stdout/exit codes only | Claude Code docs | No direct inter-hook communication; use filesystem for state |
| Prompt hooks add ~1-2s latency (Haiku call) | Measured | Avoid prompt hooks on high-frequency events (Edit/Write) |
| Agent hooks add ~5-30s latency | Claude Code docs | Only viable for Stop hooks, not per-tool-call hooks |
| Environment variables in hooks require shell profile sourcing | Claude Code docs | `bash -lc` prefix needed for env var access in hooks |

## Requirements

### 1. Hook Profile System
Runtime hook toggling without editing settings.json.

- 1.1: Create `lib/hook-profiles.js` that exports `isHookEnabled(hookId, { profiles })` function
- 1.2: Support three profiles: `minimal` (lifecycle + safety only), `standard` (balanced quality + safety), `strict` (all hooks enabled)
- 1.3: Read profile from `TEMPLATE_HOOK_PROFILE` env var (default: `standard`)
- 1.4: Support `TEMPLATE_DISABLED_HOOKS` env var for comma-separated hook IDs to disable
- 1.5: Each existing hook must declare which profiles it belongs to (metadata in settings.json comments or separate manifest)
- 1.6: Profile `minimal` enables: session-init, project-index, pre-commit-check, protect-sensitive-files, pre-compact, session-end, pattern-extraction
- 1.7: Profile `standard` adds: post-edit-format, console-log-audit, suggest-compact, build-analysis, pr-url-extract, observe (all current hooks)
- 1.8: Profile `strict` adds: file-size-guard, quality-gate (full), cost-tracker, typescript-check, doc-file-blocker, dev-server-blocker, long-running-tmux-hint
- 1.9: Create wrapper script that existing bash hooks can source to check profile before executing

### 2. Quality Gate Consolidation
Merge format, typecheck, and console-log-audit into one smart hook.

- 2.1: Create `quality-gate.js` as PostToolUse hook matching `Edit|Write`
- 2.2: Auto-detect project formatter: Biome (check biome.json), Prettier (check .prettierrc), ruff (check pyproject.toml/ruff.toml), gofmt (check go.mod)
- 2.3: For JS/TS files with Biome: run `biome check --write`, skip separate format step
- 2.4: For JS/TS files with Prettier: run `prettier --write`
- 2.5: For Python files: run `ruff check --fix` + `ruff format`
- 2.6: For Go files: run `gofmt -w`
- 2.7: Check for debug statements (console.log, print(), breakpoint()) in edited file
- 2.8: Run tsc --noEmit for .ts/.tsx files when tsconfig.json exists
- 2.9: Support `TEMPLATE_QUALITY_GATE_FIX=true` env var for auto-fix mode
- 2.10: Existing bash hooks (post-edit-format, console-log-audit, typescript-check) remain as fallbacks when Node.js is unavailable

### 3. File Size Enforcement Hook
Block creation of oversized files.

- 3.1: Create `file-size-guard.js` as PreToolUse hook matching `Write`
- 3.2: Count lines in `tool_input.content`; block with exit 2 if >800 lines
- 3.3: Provide actionable feedback: "File exceeds 800 lines (N lines). Split into smaller, focused modules."
- 3.4: Exempt known large files: package-lock.json, yarn.lock, generated files
- 3.5: Only active in `strict` profile

### 4. Cost Tracker Hook
Lightweight token/cost telemetry per session.

- 4.1: Create `cost-tracker.js` as async Stop hook (non-blocking, 10s timeout)
- 4.2: Read `tool_name` and approximate token usage from hook input
- 4.3: Append cost entry to `.claude/sessions/cost-log.jsonl`
- 4.4: Track: timestamp, tool_name, estimated_tokens, session_id
- 4.5: Active in all profiles (minimal overhead — async, append-only)

### 5. Harness Audit Command
Deterministic template health scoring.

- 5.1: Create `scripts/harness-audit.js` with 7-category scoring (0-10 each, 70 max)
- 5.2: Categories: Tool Coverage, Context Efficiency, Quality Gates, Memory Persistence, Eval Coverage, Security Guardrails, Cost Efficiency
- 5.3: Scores derived from explicit file/rule checks (reproducible for same commit)
- 5.4: Output: overall_score, category scores, failed checks with file paths, top 3 actions
- 5.5: Create `/harness-audit` command that runs the script and presents results
- 5.6: Support `--format text|json` for human and machine-readable output
- 5.7: Support scoped audits: `repo` (default), `hooks`, `skills`, `commands`, `agents`

### 6. Model Route Command
Model tier recommendation by task complexity.

- 6.1: Create `/model-route` command with task description input
- 6.2: Routing heuristic: haiku (deterministic, low-risk), sonnet (implementation, refactors), opus (architecture, deep review, ambiguous)
- 6.3: Output: recommended model, confidence level, rationale, fallback model
- 6.4: Support `--budget low|med|high` flag

### 7. Session Save/Resume Commands
Explicit session state management.

- 7.1: Create `/save-session` command that captures: current task, branch, uncommitted changes, key decisions, next steps
- 7.2: Save to `.claude/sessions/saved-<timestamp>.md`
- 7.3: Create `/resume-session` command that lists saved sessions and loads selected one
- 7.4: Integrate with existing handoff doc pattern (`.claude/sessions/handoff-*.md`)

### 8. Agentic Engineering Skill

- 8.2: Cover: eval-first loop (define criteria → baseline → implement → re-eval → compare)

- 8.5: Cover: cost discipline (track per-task: model, tokens, retries, wall-clock, success/failure)

### 9. Autonomous Loops Skill
Patterns for non-interactive agent work.

### 10. Eval Metrics Integration
pass@k and pass^k frameworks.

- 10.1: Create `.claude/skills/eval-metrics/SKILL.md`
- 10.2: Define pass@k: at least ONE of k attempts succeeds. Use for development iteration.
- 10.3: Define pass^k: ALL k attempts must succeed. Use for production consistency verification.
- 10.4: Provide concrete thresholds: pass@1=70%, pass@3=91%, pass@5=97% (development). pass^1=70%, pass^3=34%, pass^5=17% (production).
- 10.5: Integration with existing eval-harness skill (extend, don't replace)

### 11. Project Auto-Detection

- 11.1: Create `scripts/lib/project-detect.js` that detects languages from marker files (package.json, pyproject.toml, go.mod, Cargo.toml, etc.)

- 11.4: Integrate into `session-init.sh` — inject detected stack into session context
- 11.5: Used by quality gate hook to select correct formatter/linter

## Success Criteria

- Hook profile system works: `TEMPLATE_HOOK_PROFILE=minimal` disables non-essential hooks, `strict` enables all
- Quality gate hook correctly detects and runs Biome, Prettier, ruff, or gofmt based on project type
- File size guard blocks Write operations >800 lines with actionable feedback
- `/harness-audit` produces reproducible scores for the same commit
- `/model-route` provides reasonable model recommendations for different task types
- All 3 new skills load correctly via Skill tool and provide actionable guidance
- Security hardening rule loads at session start and deny list patterns are documented
- All existing hooks continue to function unchanged when `TEMPLATE_HOOK_PROFILE=standard`
- No regression in session startup time (< 2s total for all SessionStart hooks)

## Security Considerations

- New Node.js hooks must validate all stdin input (cap at 1MB, handle malformed JSON)
- Hook profile env vars must not be settable via tool injection (hooks read from process.env at startup, not from tool input)
- `harness-audit.js` must not execute arbitrary code — scoring is file-existence checks and pattern matching only
- AgentShield scanning should run in CI, not in hooks (too slow for per-tool-call execution)
- Deny lists in security-hardening.md are DOCUMENTATION, not hook enforcement — users must configure in their own settings.json

## Performance Requirements

- Quality gate hook must complete within 5s per file edit (formatter + lint + typecheck)
- Cost tracker hook is async with 10s timeout — must not block Claude's next response
- File size guard is synchronous but fast (line count only, no file I/O for existing files)
- Hook profile check adds <10ms overhead per hook (simple env var read + string comparison)
- Session-init with project auto-detection must complete within 3s total
- Harness audit script must complete within 15s for full repo scope
